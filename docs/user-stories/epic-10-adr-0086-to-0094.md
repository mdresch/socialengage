## Story 10.1 — Prospecting list model and sharing (backend)

**Source:** ADR-0086 (Accepted 2026-08-27) · **Status:** Ready
**Built:** 2026-08-27 — social-listening-core@6cc1089 *(Documentation Steward correction, 2026-09-12: this field previously uniformly cited `fdb9bb8` (the last commit in the Epic 10 batch) for every story 10.1–10.14 — corrected to cite the real individual commit that actually shipped this specific story, confirmed via `git diff-tree` and `docs/implementation-log.md`'s new backfill entry for this epic.)*

**As a** backend engineer,
**I want** `prospecting_lists` and `prospecting_list_entries` tables with RLS and sharing,
**so that** `Social-Selling-Strategist` can save, score, and share lead lists.

**Acceptance Criteria**
- `prospecting_lists` and `prospecting_list_entries` tables exist with tenant RLS.
- `GET /v1/prospecting-lists`, `POST`, `PATCH`, and `DELETE` are tenant-scoped and owner-scoped for writes.
- A list can be `shared` so other `tenant_user`/`tenant_admin` in the same tenant can **read** it (list + entries).
- Only the list's own `owner_id` can toggle `shared`, or create/update/delete the list or its entries — including while `shared = true`. There is no `Tenant-Admin` override (ADR-0044 §5c parity). A non-owner's write attempt on a visible shared list returns `404` (RLS match, not a role check), never `403`.
- Relationship stage values are constrained to `new`, `contacted`, `engaged`, `converted`, `passed`.
- `POST /v1/prospecting-lists/:id/entries`, `PATCH .../:entryId`, and `DELETE .../:entryId` manage entries that reference `Author` by `author_id`, with `engagement_score`/`authenticity_score`/`influence_score`/`reach_score` snapshotted from `Author` (ADR-0108) at add time.
- `POST /v1/prospecting-lists/:id/entries` on an `author_id` already in the list returns `409 Conflict` (`UNIQUE (prospecting_list_id, author_id)`).
- `GET /v1/prospecting-lists/:id/entries` is cursor-paginated (default limit 50, max 200); no fixed per-list entry cap in v1.
- `GET /v1/prospecting-lists/:id/export.csv` and `POST /v1/prospecting-lists/:id/crm-handoff` exist per this ADR's endpoint scoping, but their wire contracts are owned by ADR-0117 (export/CRM-push) and ADR-0095 (`CRMConnector`) — implement against those, not against this story directly.
- Contract tests cover CRUD, owner-only mutation on a shared list (404 for non-owner), duplicate-entry 409, and cross-tenant 404.

## Story 10.3 — Preconfigured analytics views (backend)

**Source:** ADR-0087 (Accepted 2026-08-27) · **Status:** Ready
**Built:** 2026-08-27 — social-listening-core@ffe640d *(Documentation Steward correction, 2026-09-12: this field previously uniformly cited `fdb9bb8` (the last commit in the Epic 10 batch) for every story 10.1–10.14 — corrected to cite the real individual commit that actually shipped this specific story, confirmed via `git diff-tree` and `docs/implementation-log.md`'s new backfill entry for this epic.)*

**As a** backend engineer,
**I want** `TopicDailyCount`, `SourceDailyCount`, `AuthorDailyCount`, `SentimentDailyCount`, and `WatchlistDailyCount` tables and a refresh worker,
**so that** dashboards and analytics can read fast, precomputed aggregates.

**Acceptance Criteria**
- All five daily-count tables exist with `(tenant_id, date, ...)` primary keys and indexes.
- `topic_id` foreign-keys to ADR-0104's `topics` catalog (`TopicClusteringService`) — not to `AIProviderConnector`, not to `watchlists`. Topic merges are not backfilled into historical rows; a merged topic's counts start fresh from the merge date (ADR-0104 §6).
- `sum_reach` is computed from `social_posts.author_follower_count_at_publish` (ADR-0049) and is `NULL` for organization-as-Author connectors (Newswire, GNews, Wikipedia) that report no follower count — this is expected, not a bug. `sum_engagement` is Facebook-only for v1 and `NULL` for every other connector's posts (confirmed 2026-08-27). Neither column should be assumed fully populated by any consumer.
- A `RefreshAnalyticsViews` worker runs every 15 minutes and is idempotent.
- Late-arriving posts trigger re-computation for affected `(tenant_id, date)` buckets.
- The current partial day is computed as a provisional row and overwritten on the next run; query-time callers fall back to `social_posts` for the partial day.
- `GET /v1/analytics/:view` exposes `topics`, `sources`, `authors`, `sentiments`, and `watchlists` views.
- Aggregate rows contain counts, sums, and identifiers only; no raw post bodies, `rawPayload`, or `post_id` lists are stored in the views (the `watchlist_id` itself may appear on `WatchlistDailyCount`).
- This endpoint is additive to, not a replacement for, Epic 8's existing client-side analytics dashboard (ADR-0054) — see ADR-0087 Decision §8 for exactly which Epic 8 widgets are eligible to migrate to it. Migrating them is separate, not-yet-scheduled follow-up work; this story only builds the tables, worker, and endpoint.

## Story 10.4 — Ad-hoc query endpoint (backend)

**Source:** ADR-0088 (Accepted 2026-08-28) · **Status:** Ready
**Built:** 2026-08-27 — social-listening-core@ffe640d *(Documentation Steward correction, 2026-09-12: this field previously uniformly cited `fdb9bb8` (the last commit in the Epic 10 batch) for every story 10.1–10.14 — corrected to cite the real individual commit that actually shipped this specific story, confirmed via `git diff-tree` and `docs/implementation-log.md`'s new backfill entry for this epic.)*

**As a** backend engineer,
**I want** `POST /v1/analytics/query` to accept a structured, allowlisted query and return a safe aggregation,
**so that** `Tenant-Business-Analyst` can ask custom questions without writing SQL.

**Acceptance Criteria**
- `dimensions` and `metrics` are validated against an allowlist.
- `QueryBuilder` translates the structured request into a parameterized, tenant-scoped SQL query.
- `timeGrain` supports `hour`, `day`, `week`, `month`.
- `limit` is capped at 1,000 and query runtime is capped at 30 seconds.
- The endpoint prefers `*DailyCount` tables and falls back to `social_posts` for drill-downs.
- Unknown `dimensions`/`metrics` return `400 UNKNOWN_DIMENSION` / `400 UNKNOWN_METRIC`.
- `format` supports `json` and `csv`; the endpoint is read-only.
- Response includes `columns`, `rows`, `rowCount`, `truncated`, `queryTimeMs`, and `source` (`precomputed` | `raw`).
- Per-tenant rate limit is 60 requests per minute (configurable).
- Contract tests cover allowed, disallowed, and timeout scenarios.

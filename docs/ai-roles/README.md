# AI Role Charters

Reusable prompt charters for the externally-invoked AI reviewers registered in `docs/project docs/Stakeholder-Register.md` (S-10, S-14, S-15, S-16). Each is chartered to **pull hard on one domain** rather than produce a balanced, softened summary — see the Stakeholder Register's 2026-07-31 second addendum for the design principle and its real precedent (Story 2.5's traced-blast-radius-then-pause-for-sign-off pattern in `docs/implementation-log.md`). Reconciling what the different roles argue for is Menno's job as Sponsor, not something any of these roles do for him.

These are **human-mediated by default**, not wired into this repo's `implement-story`/`heal-contract-failure` enforcement: paste the charter's prompt block into the named model's own chat session along with the material under review, then bring the findings back yourself. That stays a deliberate boundary — see `docs/implementation-plan.md`'s repeated "don't build speculatively" discipline (the same reasoning behind ADR-0020's deferred distributed rate-limit gate); wiring these into the mandatory methodology would be a real, separate decision, not a side effect of defining the charters.

**One exception, added 2026-07-31:** the Engineering Pragmatism Reviewer (Mistral) can also be invoked via real API automation, `docs/ai-roles/scripts/invoke-mistral-agent.cjs`, once its Mistral-hosted agent is configured with the charter below as its system instructions. Setup: copy `docs/ai-roles/.env.example` to `docs/ai-roles/.env` (gitignored — never commit real values) and fill in `MISTRAL_API_KEY` and the agent's ID. **A second exception, also added 2026-07-31:** the Data Privacy & Sovereignty Reviewer now has its own automated path too — `docs/ai-roles/scripts/invoke-ollama-agent.cjs` — but it's deliberately different in kind from the Mistral one: it only ever calls Ollama's *local* REST API (`localhost:11434`, no network egress to any third party), reads this charter's own "Prompt block" fresh from the `.md` file on every run instead of relying on a separately-configured hosted agent, and hard-refuses to run against any `:cloud`-suffixed Ollama model (Ollama's own hosted-proxy models, which would defeat the entire point). Setup: install Ollama and pull a model — no `.env`, no API key. Connectivity-tested 2026-07-31 on `qwen2.5:0.5b` (works, but too small for a substantive review); two larger local candidates (`llama3.1:8b`, `qwen2.5:3b`) both failed to load in this environment on memory-allocation errors, not a model-size-specific problem.

For the roles Claude Code *can* run natively as subagents (no human-mediated copy/paste needed), see `.claude/agents/`: `ba-requirements-analyst.md`, `qa-contract-author.md`, `documentation-steward.md`, the three `persona-*.md` persona-proxy agents, and `ideal-manager.md`. These plus the AI Delivery Agent itself are registered as **Governed** rather than externally invoked (Stakeholder Register S-09, S-11, S-12, S-13, S-17–S-19, S-20) — see that register's Section 3 for what each one actually does and, for the persona-proxy agents specifically, the hard limit on what their output is worth (design-time hypothesis, never real user validation).

| Role | Model | Domain Pull | Charter |
|---|---|---|---|
| Security & Architecture Reviewer | Gemini (primary; Copilot historically) | Trust boundaries, risk — argue for hardening | [`security-architecture-reviewer.md`](security-architecture-reviewer.md) |
| Product & Market-Fit Reviewer | Mistral (reassigned from OpenAI, 2026-07-31 — see charter) | Would a real tenant value this? | [`product-market-reviewer.md`](product-market-reviewer.md) |
| Engineering Pragmatism Reviewer | Mistral | Simplicity — argue against overengineering | [`engineering-pragmatism-reviewer.md`](engineering-pragmatism-reviewer.md) |
| Data Privacy & Sovereignty Reviewer | Ollama (local) | Data minimization, no unnecessary third-party exposure | [`data-privacy-sovereignty-reviewer.md`](data-privacy-sovereignty-reviewer.md) |

Product & Market-Fit and Engineering Pragmatism are two *separately configured* Mistral agents (different `agent_id`s, different personas, same account) — `docs/ai-roles/scripts/invoke-mistral-agent.cjs` takes a `--role pragmatism|product-market` flag to pick between them. This means two of the four external reviewers now share an underlying model, which dilutes some of the epistemic-diversity reasoning that motivated spreading roles across providers in the first place — accepted for practical reasons (OpenAI API access wasn't available on Menno's free-tier account), not because that reasoning stopped mattering.

**Status as of 2026-07-31:** the Security & Architecture Reviewer role has the strongest real track record (Copilot's review produced ADR-0017/0018/0020–0023; Gemini's 2026-07-30 review produced the three findings logged in `docs/implementation-methodology.md`'s "Deferred findings" section), but is not yet automated. Engineering Pragmatism (Mistral), Product & Market-Fit (Mistral), and Data Privacy & Sovereignty (Ollama) all have working, connectivity-tested automation — each confirmed to correctly self-identify its role and domain pull, but none has produced a real design-review finding against actual project material yet.

**Status correction, 2026-08-03:** the Security & Architecture Reviewer is now automated too — `docs/ai-roles/scripts/invoke-gemini-agent.mjs` — and, after fixing a real bug where `systemInstruction` was silently never reaching the API (see the charter's own second 2026-08-03 Correction note), has produced a genuine, correctly-formatted findings list against real project material. It also gained a persistent output: `--register` attaches `docs/security/security-register.md`'s current content as context and appends the new dated finding to it (append-only, same discipline as `docs/implementation-log.md`), so findings accumulate across sessions instead of vanishing into a terminal scrollback each time.

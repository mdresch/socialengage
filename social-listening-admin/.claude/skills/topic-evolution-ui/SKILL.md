# Topic Evolution Timeline UI

Governed by **ADR-0097**, **BRD-0097**, **FDD-0097**, **Story 11.6**, and **ADR-0116** / **Story 13.12** (semantic drift UI).

## Contracts that constrain this component

- `social-listening-admin/contracts/epic-11/story-11.6.topic-evolution-ui.contract.test.ts` — Story 11.6 contract test.
- `social-listening-admin/contracts/epic-13/story-13.12.semantic-drift-ui.contract.test.ts` — Story 13.12 contract test covering the drift warning icon, DriftExplanationCard, RAG summary, and date range selector.

## Key Responsibilities

1. **`core-client.ts` Integration**:
   - `getTopicEvolution(options)`: Fetches longitudinal time-series data with points, sentiment distributions, top keywords, driver authors, and 7-day slope trend indicators.
   - `getTopicDrift(topicId, start, end)`: Fetches a `TopicDriftResult` from `GET /v1/topics/:id/drift` (Story 13.12 / ADR-0116).

2. **BFF Proxy Handlers**:
   - `/api/topics/evolution`: Proxy for authenticated topic evolution queries.
   - `/api/topics/drift`: Proxy for authenticated semantic-drift queries (Story 13.12).

3. **`TopicEvolutionTimeline.tsx` Component**:
   - Multi-series volume bar visualization with stacked sentiment colors.
   - `TrendAnnotation` badge displaying `rising` (🔥), `falling` (📉), or `stable` (➡️).
   - `AuthorSparkline` (top driver authors) and `KeywordHeatmap` (top keywords frequency breakdown) detail cards.
   - Interactive date range, topic selector, and granularity controls (`day`, `week`, `month`).
   - `compareToPrevious` overlay for period-over-period trend analysis.
   - Deep linking synchronization via query params (`topic`, `granularity`, `compareToPrevious`).
   - Drift warning icon (⚠️) when `getTopicDrift()` returns `warning: 'significant'` (Story 13.12 / ADR-0116).
   - Date-range selector for the two drift comparison windows and a call to `/api/topics/drift` (Story 13.12).

4. **`DriftExplanationCard.tsx` Component** (Story 13.12):
   - Displays `topClustersNow`, `topClustersThen`, `samplePostsNow`, and `samplePostsThen`.
   - Calls `RAGAsk` (`/api/rag/ask`) to generate a plain-language drift summary from the cluster/sample data.

## Load-bearing constraints — do not change casually

- `getTopicDrift()` must call through `core-client.ts` (ADR-0001) and therefore through `authenticatedCoreFetch()`; it must never call core's database or an in-process core module.
- The drift warning must be driven by the backend `warning` value, not a client-side re-derivation of `driftScore` thresholds, so the UI stays aligned with ADR-0116's threshold rules.
- The RAG summary must be generated by the existing `/api/rag/ask` BFF route (ADR-0084/0085) rather than duplicating the prompt or model call inside the admin component.
